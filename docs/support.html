Table caching

Connection reuse and planning metadata are cached. VGI result rows are not.

  • Worker connections, attach handles, table binds, and scalar return types are reused.
  • Split-plan cache age and locality metadata are retained for execution.
  • The adapter does not consult vgi_client::ResultCache or store batches from vgi.cache.*.
  • No whole-scan, per-value, disk, revalidation, cache inspection, or cache-control SQL surface yet.
Partial

Logging

Worker messages are visible, but not through the DuckDB-style SQL experience.

  • In-band worker logs map to Rust's log facade under target vgi::worker.
  • Structured extras are preserved as JSON text; exception batches become query errors.
  • No CALL enable_logging, duckdb_logs() equivalent, queryable log store, or VGI lifecycle/cache events.
RUST_LOG='vgi::worker=debug' \
  ./target/release/datafusion-cli

Capability matrix

What maps today

“Partial” means the protocol or Rust client has more capability than the DataFusion adapter currently exposes—not that the supported subset is experimental.

Catalog & connectivity
ATTACH / DETACH
Supported
DuckDB-style and query-string forms, optional aliases, local connection options, and worker-declared typed options mount a remote catalog. Required and unknown options are validated before attach.
Catalog discovery
Supported
Schemas, tables, table functions, scalar functions, aggregate functions, and scalar SQL macros are discovered and registered.
Transports
Supported
Bare subprocess commands, HTTP, Unix sockets, TCP, and shared launch: workers use the same LOCATION spelling as DuckDB.
Connection pooling
Supported
Each DataFusion scan partition gets an independent VGI connection; idle connections and attach handles are reused.
Authentication
Supported
HTTP attaches recover from 401 via RFC 9728 discovery and OAuth device flow, or accept bearer_token / oauth_refresh_token. Credentials are redacted, session-only, single-flight across partitions, and isolated in the pool.
Transactions & time travel
Not wired
No DataFusion transaction lifecycle bridge, catalog version pinning, or VGI AT clause surface.
Functions & SQL
Producer table functions
Supported
Constant positional and named arguments bind through DataFusion table functions, including catalog scan functions.
Scalar functions
Supported
Async scalar UDFs execute columnar batches; const parameters are separated at bind and output types are memoized.
Aggregate functions
Partial
Results are correct, including grouped aggregates, but inputs are buffered locally per group because VGI aggregate state cannot be serialized across DataFusion's partial/final stages.
Scalar SQL macros
Supported
Qualified catalog macros expand locally into DataFusion expressions; the Open-Meteo weather-code helpers use this path.
Table-in/out & buffered
Partial
Literal blended calls and buffered/exchange functions work. A DataFusion scalar subquery can supply only one input column.
Correlated LATERAL calls
Not wired
DataFusion binds a table function before outer rows exist, so LATERAL forecast(g.latitude, g.longitude) still requires a two-step query.
EXPLAIN
Supported
The VGI rewrite now traverses DataFusion's EXPLAIN wrapper, including named table-function arguments and Unicode macro expressions.
Optimizer & execution
Projection & LIMIT pushdown
Supported
Projected columns and row limits reach bind, split planning, and scan. Empty projection for count(*) uses the narrowest physical column.
Static filter pushdown
Supported
Supported predicates are serialized for VGI and conservatively marked inexact, so DataFusion rechecks them locally for correctness.
Split planning
Supported
Pagination, max-workers enforcement, byte-weighted bin packing, zero/empty splits, execution context, and independent split redemption are covered.
Statistics
Supported
Plan and split row/byte estimates plus per-column statistics and partition bounds feed DataFusion's statistics API with appropriate exactness.
Ordering
Partial
Within-split ordering is advertised when each physical partition owns exactly one split. ORDER BY hints are not pushed from DataFusion into VGI planning.
Positions & streaming
Partial
Bounded start/end positions are preserved. Unbounded splits are refused because the current execution plan declares bounded tasks.
Locality & partition transforms
Partial
Location hints and transforms survive in the plan, but DataFusion has no scheduler-affinity hook and VGI hash semantics are not assumed to match DataFusion's.
Dynamic filters & join keys
Not wired
There is no runtime bridge from DataFusion joins into VGI continuation ticks. Ordinary static predicates remain supported.
Table sampling & order hints
Not wired
DataFusion's current table-provider scan callback does not expose the VGI sample and order-hint surfaces used by DuckDB.
Cancellation
Partial
Dropping a scan consumer or satisfying a LIMIT sends protocol cancellation to the active scan. Connection, bind, and split-planning calls are still synchronous spawn_blocking work and cannot be interrupted mid-call.
Caching, observability & mutation
Planning / metadata cache
Partial
Attach handles, table binds, scalar return types, and worker connections are memoized. Split-plan cache age is retained but not used by a reusable plan cache.
VGI result cache
Not wired
The adapter neither probes nor populates the Rust client's in-memory result cache, despite parsing worker cache-control metadata.
Worker logs
Partial
Available through RUST_LOG as vgi::worker; structured SQL-visible logs, lifecycle events, and cache events are absent.
Writes, DDL & COPY
Not wired
INSERT, UPDATE, DELETE, writable branches, catalog DDL, COPY formats, and secret providers have no DataFusion integration yet.

Implementation backlog

What is left

Ordered by what most improves operability and real workloads. Each card names an implementation boundary, not just a broad feature wish.

01 · Ship

Publish and distribute

Turn the working local integration into a reproducible artifact rather than a sibling-checkout build.

  • Publish vgi-datafusion against DataFusion 55.
  • Upstream or maintain the small DataFusion CLI integration patch.
  • Add release CI and packaged CLI artifacts.
02 · Operate

Structured observability

Expose more than worker text through RUST_LOG.

  • Add a session-scoped event sink for worker, RPC, split, and cache events.
  • Attach query, function, split, duration, and structured-extra fields.
  • Offer CLI output and an embedder API; decide whether SQL-queryable history is appropriate.
03 · Accelerate

Wire in result caching

Use the cache facilities and metadata that the Rust client already exposes.

  • Own a bounded cache per DataFusion session.
  • Build complete keys including catalog version, arguments, projection, filters, and auth scope.
  • Expose hit/miss/eviction statistics, invalidation, and memory limits.
04 · Express

Correlated LATERAL execution

Make a table-function call depend on columns from each outer row, enabling the one-statement geocode-to-forecast example.

  • Add an execution-time table-function operator.
  • Define concurrency, ordering, backpressure, and error semantics.
  • Avoid one uncontrolled connection per input row.
05 · Secure

Secret resolution

Authentication is wired; the remaining security gap is referring to credentials without embedding them in SQL text.

  • Integrate a named secret resolver for embedders and the CLI.
  • Define refresh-token persistence as an explicit opt-in, separate from session state.
  • Carry auth identity into future result-cache keys without storing token material.
06 · Interrupt

End-to-end cancellation

Extend active-scan cancellation to every blocking RPC phase.

  • Make connect, attach, bind, and plan calls cancellation-aware.
  • Propagate DataFusion task cancellation and deadlines.
  • Test stalled workers before and after scan creation.
07 · Optimize

Runtime and ordering hints

Bridge optimizer information that currently stops at the DataFusion boundary.

  • Push ORDER BY and sampling hints where semantics match.
  • Connect runtime join filters to VGI continuation ticks.
  • Use locality only when a scheduler-affinity contract exists.
08 · Generalize

Richer table input

Remove the scalar-subquery restriction that limits exchange functions to one input column.

  • Represent multi-column table arguments in the logical plan.
  • Preserve schema and partitioning through buffered/exchange calls.
  • Cover wide, empty, and multi-partition inputs.
09 · Stream

Unbounded split execution

Support start-only streaming positions with an execution plan that honestly declares unbounded output.

  • Map VGI positions to DataFusion stream semantics.
  • Define checkpoints, reconnects, and cancellation.
  • Keep bounded scans unchanged.
10 · Mutate

Writes and versioned catalogs

Add the protocol surfaces outside today’s read/query focus.

  • INSERT, UPDATE, DELETE, DDL, and COPY integration.
  • Transaction lifecycle and catalog-version pinning.
  • Time-travel and writable-branch SQL design.

Production gate status: authentication and fresh shared SQLLogicTest runs are complete (Unix: 283 executed / 50 gated skips / 10,722 assertions; HTTP: 288 / 45 / 10,767). Publishing, structured observability, and cancellation timeout coverage remain release gates. Result caching and correlated LATERAL execution are high-value follow-ons, but do not need to block a read-only preview if their absence is documented.
