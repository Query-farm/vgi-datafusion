Table caching

Worker-opted-in producer results now use a bounded, session-local memory cache.

  • Worker connections, attach handles, table binds, and scalar return types are reused.
  • Complete ordinary and split scans commit atomically; errors, cancellation, abandoned LIMITs, and incomplete partitions never store partial rows.
  • Keys isolate auth identity, catalog/version, arguments, attach options, projection, filters, and limit; ordered split results are refused when replay could invalidate plan properties.
  • ETag/Last-Modified revalidation, stale-if-error, and per-key single-flight work for eligible entries. Exchange/per-value, per-partition, disk, and stale-while-revalidate tiers remain future work.
  • Inspect with vgi_cache_stats(), vgi_cache_entries(), and vgi_plan_cache_stats(); maintain with vgi_cache_flush() and vgi_cache_reap().
  • Read the code-backed cache phases and full implementation inventory →
Partial

Logging

Worker text and structured adapter lifecycle events are both visible.

  • In-band worker logs map to Rust's log facade under target vgi::worker.
  • Structured extras are preserved as JSON text; exception batches become query errors.
  • Attach, plan, scan, cancellation, error, and cache events go to an embedder VgiEventSink and a bounded session history.
  • Query history with vgi_logs() and vgi_log_stats(); clear it with vgi_logs_clear(). Worker text remains in Rust log, not duplicated into SQL history.

Capability matrix

What maps today

“Partial” means the protocol or Rust client has more capability than the DataFusion adapter currently exposes—not that the supported subset is experimental.

Catalog & connectivity
ATTACH / DETACH
Supported
DuckDB-style and query-string forms, typed worker options, cache veto, and VGI-only companion attachments are supported. DETACH removes the alias-owned flat function registrations.
Catalog discovery
Supported
Schemas, tables, views, table/scalar/aggregate functions, scalar and table SQL macros, and worker-nominated global functions are discovered and registered.
Native format branches
Supported
Worker-nominated CSV, Parquet, JSON/NDJSON, and Arrow scan arms use DataFusion's registered file-format factories and listing providers. Typed options, schema reconciliation, exact CSV null markers, and eligible native filter pushdown are preserved. Non-loopback workers need an explicit trust opt-in before they may nominate client-local paths.
Catalog-table branches
Supported
Companion source arms resolve existing DataFusion providers by attachment alias or unique worker-catalog identity, reuse reconciliation and filter pushdown, and reject direct or indirect source cycles.
SQL metadata
Supported
DataFusion SHOW TABLES, SHOW COLUMNS, SHOW FUNCTIONS, and information_schema expose VGI relations, schemas, columns, views, and routines. Catalog schemas come directly from discovery; scan functions bind only when queried.
Constraint metadata
Partial
VGI primary-key and unique constraints feed DataFusion's native provider constraint API. DataFusion has no native check, foreign-key, standalone NOT NULL, or DuckDB-compatible duckdb_constraints() metadata table.
Transports
Supported
Bare subprocess commands, HTTP, Unix sockets, TCP, and shared launch: workers use the same LOCATION spelling as DuckDB.
Connection pooling
Supported
Each DataFusion scan partition gets an independent VGI connection; idle connections and attach handles are reused.
Authentication
Supported
HTTP attaches recover from 401 via RFC 9728 discovery and OAuth device flow, or accept bearer_token / oauth_refresh_token. Credentials are redacted, session-only, single-flight across partitions, and isolated in the pool.
Worker secrets
Supported
An embedder-installed async VgiSecretResolver drives one-retry scoped binds and statically declared aggregate secrets without placing credential values in SQL, cache keys, logs, or diagnostics.
Table time travel
Supported
Fully-qualified VGI catalog tables accept literal AT (VERSION => …) and AT (TIMESTAMP => …). Historical schema evolution is planned correctly, the coordinate reaches bind/plan/scan, and result plus split-plan caches isolate each coordinate.
Transactions & snapshot pinning
Not wired
DataFusion transaction statements are not bridged to VGI, and there is no catalog-wide snapshot pinning lifecycle.
Functions & SQL
Producer table functions
Supported
Constant positional and named arguments bind through DataFusion table functions, including catalog scan functions.
Scalar functions
Supported
Async scalar UDFs execute columnar batches; const parameters are separated at bind, output types are memoized, and overload selection preserves VGI type-family compatibility instead of casting into incompatible arms.
Aggregate functions
Partial
Grouped aggregates and bind-time ConstParams are correct, but inputs are buffered locally per group because VGI aggregate state cannot be serialized across DataFusion's partial/final stages.
Scalar & table SQL macros
Supported
Qualified catalog macros expand locally into existing DataFusion expressions or derived relations. Typed defaults, positional and named arguments, nested scalar expansion, and deterministic recursion errors are supported.
Views & global functions
Supported
Worker view SQL is qualified and installed as DataFusion ViewTables. Explicit global scalar, aggregate, table, and buffered functions use the VGI prefix and collision policy.
Window aggregates
Partial
Advertised sliding aggregates use the dedicated VGI window callback through DataFusion's sliding-accumulator API; ordinary grouping keeps aggregate update/finalize semantics. DataFusion 55 does not support window EXCLUDE or aggregate-local ORDER BY forms.
Table-in/out & buffered
Partial
Literal blended calls and buffered/exchange functions work. A DataFusion scalar subquery can supply only one input column.
Correlated LATERAL calls
Not wired
DataFusion binds a table function before outer rows exist, so LATERAL forecast(g.latitude, g.longitude) still requires a two-step query.
EXPLAIN
Supported
The VGI rewrite now traverses DataFusion's EXPLAIN wrapper, including named table-function arguments and Unicode macro expressions.
Optimizer & execution
Projection & LIMIT pushdown
Supported
Projected columns and row limits reach bind, split planning, and scan. Empty projection for count(*) uses the narrowest physical column.
Static filter pushdown
Supported
Supported predicates are serialized for VGI. Direct table functions preserve exact worker application; lazy catalog tables conservatively recheck because their scan function is resolved after metadata planning.
Split planning
Supported
Pagination, max-workers enforcement, byte-weighted bin packing, zero/empty splits, execution context, and independent split redemption are covered.
Statistics
Supported
Plan and split row/byte estimates plus per-column statistics and partition bounds feed DataFusion's statistics API with appropriate exactness.
Ordering
Partial
Within-split ordering is advertised when each physical partition owns exactly one split. ORDER BY hints are not pushed from DataFusion into VGI planning.
Positions & streaming
Partial
Start-only plans now declare honest DataFusion unbounded output. Checkpoint/reconnect policy and advertised resume gating still need production hardening.
Locality & partition transforms
Partial
Location hints are exposed through an embedder scheduler hook, and bounds feed statistics. VGI hash transforms are not assumed to match DataFusion partition semantics.
Dynamic filters & join keys
Partial
DataFusion 55 runtime filters are linked to VGI scans. Single-column join sets use version-2 join-key side IPC at init; later constant/range generations use base64 vgi_pushdown_filters across subprocess, Unix/TCP, and plain or authenticated HTTP continuations. Large hash-lookup and multi-column struct expressions remain local, and dynamic scans bypass result caching.
Table sampling & order hints
Not wired
DataFusion's current table-provider scan callback does not expose the VGI sample and order-hint surfaces used by DuckDB.
Cancellation
Partial
Dropping a scan consumer or satisfying a LIMIT sends protocol cancellation to the active scan. Connection, bind, and split-planning calls are still synchronous spawn_blocking work and cannot be interrupted mid-call.
Caching, observability & mutation
Planning / metadata cache
Supported
Attach handles, binds, return types, and connections are memoized. Catalog-scoped split plans reuse the worker's advertised maximum age and catalog-version identity.
VGI result cache
Partial
Bounded session-memory caching is wired for complete producer scans and splits, with identity-safe keys, diagnostics, conditional revalidation, stale-if-error, and per-key single-flight. Exchange/per-value, persistent disk, and stale-while-revalidate are not wired.
Structured logs
Supported
Worker text uses vgi::worker; bounded SQL-visible lifecycle/cache history, grouped stats, clear, and an embedder event sink are available.
Writes, DDL & COPY
Not wired
INSERT, UPDATE, DELETE, writable branches, catalog DDL, custom COPY formats, and SQL CREATE SECRET integration are not wired.

Implementation backlog

What is left

Ordered by what most improves operability and real workloads. Each card names an implementation boundary, not just a broad feature wish.

01 · Ship

Publish and distribute

Turn the working local integration into a reproducible artifact rather than a sibling-checkout build.

  • Publish vgi-datafusion against DataFusion 55.
  • Upstream or maintain the small DataFusion CLI integration patch.
  • Add release CI and packaged CLI artifacts.
02 · Cache

Extend the result cache

The safe memory-backed producer tier and per-key single-flight are complete; add breadth only where VGI and DataFusion have matching semantics.

  • Add bounded stale-while-revalidate.
  • Add exchange/per-value and single-value partition entries.
  • Consider a persistent Arrow IPC tier only after transport-parity failure tests.
03 · Operate

Finish observability edges

Lifecycle/cache events are queryable; worker text and host tracing can be joined more tightly.

  • Forward structured worker extras into the event sink without duplicating credentials.
  • Add query/execution IDs supplied by embedders.
  • Add deadline and stalled-worker coverage for every transport.
04 · Express

Correlated LATERAL execution

Make a table-function call depend on columns from each outer row, enabling the one-statement geocode-to-forecast example.

  • Add an execution-time table-function operator.
  • Define concurrency, ordering, backpressure, and error semantics.
  • Avoid one uncontrolled connection per input row.
05 · Secure

CLI secret mappings

The embedder resolver and VGI bind protocol are wired; the stock CLI still needs an explicit environment-to-secret mapping surface.

  • Map named environment variables to typed secret fields without reading arbitrary process environment.
  • Keep refresh-token persistence an explicit opt-in.
  • Add scoped multi-secret CLI tests.
06 · Interrupt

End-to-end cancellation

Extend active-scan cancellation to every blocking RPC phase.

  • Make connect, attach, bind, and plan calls cancellation-aware.
  • Propagate DataFusion task cancellation and deadlines.
  • Test stalled workers before and after scan creation.
07 · Optimize

Runtime and ordering hints

Extend the optimizer information that now crosses the DataFusion boundary.

  • Push ORDER BY and sampling hints where semantics match.
  • Represent large hash-lookup and multi-column dynamic join filters.
  • Use locality only when a scheduler-affinity contract exists.
08 · Generalize

Richer table input

Remove the scalar-subquery restriction that limits exchange functions to one input column.

  • Represent multi-column table arguments in the logical plan.
  • Preserve schema and partitioning through buffered/exchange calls.
  • Cover wide, empty, and multi-partition inputs.
09 · Stream

Harden unbounded splits

Plans now declare unbounded output; make long-lived execution recoverable.

  • Gate resume on worker advertisement.
  • Define checkpoints, reconnects, and cancellation.
  • Add soak and backpressure tests.
10 · Mutate

Writes and transactions

Add the protocol surfaces outside today’s read/query focus.

  • INSERT, UPDATE, DELETE, DDL, and COPY integration.
  • Transaction lifecycle and catalog-version pinning.
  • Writable-branch SQL design; table-level read-only time travel is already supported.
